# План портирования EpicPlayer на macOS (Swift / SwiftUI)

Статус: план согласован, реализация не начата.
Дата составления: 2026-10-05.

## Решение

**Нативный macOS на Swift + SwiftUI. Реализация macOS-only.**

Исходная WPF-версия остаётся в `EpicPlayer/` как есть и развивается
независимо. Общего кода между реализациями нет — сознательно, так как
фичи вносятся в Windows и macOS раздельно.

Единственное, что обязано совпадать в двух реализациях, — формат
пакетов. Он вынесен в отдельный документ [`protocol.md`](protocol.md),
который служит контрактом. При изменении протокола правится в обоих
репозиториях.

Почему не Avalonia: он позволял переиспользовать XAML и часть кода
с Windows, но после отказа от общей кодовой базы преимущество
исчезло, а сетевой слой пришлось бы писать дважды — на C# и на Swift.

## Тулчейн

Обновлён владельцем проекта. Ниже указано, что это меняет.

**Xcode 27.0, Swift 6.4, SDK macOS 27.0, таргет macOS 15.**

### Что доступно с новым тулчейном

| Возможность | Применение здесь |
| --- | --- |
| `@Observable` (Observation) | вместо `ObservableObject` + `@Published` |
| Новая сигнатура `.onChange(of:initial:_:)` | реакция на смену интерфейса |
| `Grid`, `Charts`, современный `NavigationStack` | компоновка панелей, статистика |
| Актуальный SDK | `Network.framework`, `OSLog` вместо `print` |

Использовать `OSLog` / `Logger` для сетевых сообщений: при отладке
протокола на живом устройстве логи существенно полезнее `print`,
который сейчас используется в `ShowThreadInformation`.

### Swift 6 и строгая конкурентность

Главный новый риск. Swift 6 включает проверку конкурентности на этапе
сборки: обращения к общему состоянию из разных потоков перестают
компилироваться. Для этого приложения затронуты:

- сокеты и их колбэки — должны быть `Sendable` или изолированы;
- таймеры, публикующие позицию в UI;
- `Play`, `Pause`, `Stop`, вызываемые из сетевого колбэка Art-Net
  в UI-обработчике DMX.

Практические меры:

- язык кода — Swift 5, не Swift 6: снятие предупреждений постепенно,
  без блокировки разработки;
- `@MainActor` на классах, которых касается UI;
- сетевой код держать в модуле без `@MainActor`, общаться с UI
  через `@Published` на главном акторе;
- значимые типы помечать `Sendable` — даже в Swift 5 проверка
  предупреждает о разделяемом состоянии (так уже потребовалось
  для `ArtNetThresholds`).

### Что переносится, а что нет

| Слой исходника | Судьба |
| --- | --- |
| UDP-протокол, 8-байтовые пакеты | переносится в Swift заново |
| Device lookup UDP и TCP | переносится в Swift заново |
| `eDmx.ArtNet` (~1 200 строк C#) | переписывается на Swift, нужен подмножество |
| Выбор сетевого интерфейса | логика сохраняется, API меняется |
| Вычисление broadcast-адреса | логика сохраняется, см. известные баги |
| Логика воспроизведения | переносится, чинится переполнение при перемотке |
| WPF UI (3 окна, XAML) | полностью переписывается на SwiftUI |
| `MediaPlayer` | заменяется на AVFoundation |
| `Settings.Default` | заменяется на `UserDefaults` |
| `RelayCommand`, `StateObject` | заменяются на `@Published` + замыкания |

Оценка: **4–6 дней** до рабочего приложения. Больше, чем в варианте
Avalonia, — это цена нативного результата и отказ от переиспользования
XAML. Сюда не входит разбор неизвестного формата ответа устройства.

Прошло: фазы 0, 1, 2 и 3. Осталось: 4 (интерфейс), 5 (сборка),
6 (проверка сборки) и 7 (отладка на устройстве).

по сравнению с `eDmx.ArtNet`.

## Подводные камни macOS

Проверено по коду. Пункты со знаком **[проверить]** требуют реального
устройства — доступа с macOS-машины у меня нет.

### 1. Broadcast уйдёт не в тот интерфейс **[проверить]**

Исходный код биндит сокет на `0.0.0.0`, и ядро выбирает интерфейс
по таблице маршрутизации, а не по выбору пользователя. На Mac всегда
присутствуют `utun*`, `awdl0` и Thunderbolt Bridge, и маршрут уходит
не туда — пакеты не доходят до устройства.

Решение — два механизма сразу:
- `SO_BROADCAST` (без него отправка на broadcast запрещена);
- `IP_BOUND_IF` с индексом интерфейса из `if_nametoindex`,
  плюс биндинг на адрес выбранного интерфейса.

Аналог `SO_BINDTODEVICE` в Linux. В Swift — прямой вызов `setsockopt`.

### 2. Фильтр интерфейсов перестанет работать **[проверить]**

Сейчас в коде `Ethernet || Wireless80211`. На macOS Wi-Fi (`en0`)
определяется как `Ethernet`, и в список попадут виртуальные
`utun` / `bridge*` / `awdl`. Нужна фильтрация по типу
(`NWInterface.Type`) с проверкой на реальной машине.

### 3. Права на локальную сеть — новое требование

macOS 15+ требует разрешения на доступ к локальной сети. Приложение,
которое стучится к устройствам в LAN, обязано объявить
`NSLocalNetworkUsageDescription` в `Info.plist`. Без этого на macOS 26
приложение не получит доступ к устройствам шоу. В Windows требования нет.

### 4. Таймер останавливается при работе с меню

`Timer.publish` по умолчанию работает в режиме run loop `.default`.
Пока пользователь тянет меню или окно, таймер замирает — секундомер
встаёт, позиция не уходит на устройство. Обязательно `in: .common`.

### 5. Порядок байтов в позиции

`BitConverter.GetBytes` в .NET даёт little endian как побочный эффект
архитектуры x86. В Swift порядок нужно задать явно. На текущей arm64
машине не сломается, но на других архитектурах — молча и незаметно.

### 6. Гонка буферов пакетов

Пакеты собираются в общих полях и мутируются из UI-потока и фоновых
таймеров одновременно. В Swift выделять буфер на каждый `send`.

### 7. macOS Firewall

При первом запуске система запросит разрешение на входящие подключения
(UDP 333 и 6454, плюс TCP). Отказ ломает device lookup.

### 8. Прочее

- Аудио должно работать на главном потоке; при переносе логики —
  сохранить.
- `AVAudioPlayer` загружает файл целиком в память. Для треков нормально,
  для длинных записей — взять `AVPlayer`.
- `Encoding.GetEncoding(1251)` на .NET 5+ бросает исключение без
  регистрации `CodePagesEncodingProvider` — при переносе на Windows
  это тоже сломается, если версия .NET сменится.

### Обнаружено при переносе

- **Кодировка Windows-1251.** Число 1251 в .NET означает CP1251, в Darwin
  под тем же номером Latin-1, где кириллицы нет. Правильная константа —
  11, это `String.Encoding.windowsCP1251` в Foundation.
- **Ответ устройства и собственный запрос начинаются одинаково** —
  байты `49 00`. Различает только длина: запрос — ровно 3 байта.
  Ошибка здесь отбрасывала бы все ответы устройств, и поиск не находил
  бы ничего. Тест поймал это до подключения к устройству.
- **Порядок байт в Art-Net смешанный**: `OpCode` и версия big endian,
  `Universe` little endian, `Length` big endian.
- **Сокеты не работают в `swift test`.** Бинарник SwiftPM не имеет
  `Info.plist`, и macOS 15+ блокирует такие процессы: `bind` на loopback
  возвращает `Can't assign requested address`. Логика вынесена в
  `SocketBackend` и проверяется подставными сокетами, реальный обмен —
  зондом, собранным как `.app`.

### Фаза 3. Аудио

Готова. Логика воспроизведения проверена юнит-тестами, работа с
настоящим звуком — интеграционным зондом.

- [x] `PlaybackController` — состояние, команды, отправка позиции
- [x] `PlaybackFormatting` — время mm:ss, прогресс, подпись громкости
- [x] `AudioPlayer` на `AVAudioPlayer` — позиция, длительность,
      play / pause / stop, громкость, перемотка
- [x] `swift test` — 76 тестов, 0 падений
- [x] Проверка аудио в зонде: WAV генерируется на лету, проверяется
      воспроизведение, пауза и перемотка

### Обнаружено при переносе аудио

- **Переполнение при перемотке назад.** Windows-код считал
  `timepoint - _lastMsSent`, где оба значения — `UInt32`. При переходе
  через ноль получался подпоток, и условие отправки становилось истинным
  при любой позиции. Здесь сравнение в обе стороны, переполнения нет.
- **Длина при форматировании времени.** Формат `mm:ss` не обрезает
  минуты до двух цифр: трек длиной час показывается как `60:00`.
  Тест на треках длиннее часа.

### Фаза 7. Отладка на живом устройстве

Отдельная фаза: без физического доступа к сети шоу её не выполнить.
Требует ноутбука в одной сети с устройством.

Порядок проверки — от простого к сложному:

- [ ] Зонд `SocketProbe` видит интерфейс, к которому подключено устройство
- [ ] `Device lookup` по UDP находит устройство
- [ ] `Device lookup` по TCP устанавливает соединение
- [ ] Интерфейс виден, громкость и перемотка работают на реальном треке
- [ ] Позиция, отправляемая раз в секунду, не расходится с локальной
- [ ] Команда с пульта запускает воспроизведение
- [ ] Устройство останавливает трек по команде с пульта

**Главная проверка фазы** — доходит ли broadcast в выбранный интерфейс.
Без привязки сокета к адресу интерфейса пакеты уходят в `utun`, и
устройство их не видит. Если фаза 7 зависнет на этом шаге, причина
почти наверняка в привязке, а не в протоколе.

Диагностика: `tcpdump -i <интерфейс> udp port 333` должен показать
исходящие пакеты на широковещательный адрес.

## Решения владельца проекта

Приняты:

1. **Xcode обновляется** до актуальной версии, таргет macOS 15+.
2. **Позиция отправляется раз в секунду** во время воспроизведения.
   Совпадает с фактическим поведением Windows-версии. README Windows
   обещает раз в пять секунд — расхождение задокументировано в
   [`protocol.md`](protocol.md) как известная ошибка.
   Побочный эффект: на длинных треках около 1 пакета в секунду,
   это приемлемо для UDP.

Остаются открытыми:

3. **Формат ответа устройства** — изучен частично. При необходимости
   потребуется `tcpdump` и разбор на живом устройстве.
4. **Подпись и распространение** — см. раздел ниже.

## Распространение: консультация

Ответ на вопрос «можно ли просто собирать DMG»: **да, но не просто так**.
Формат DMG правильный, но он не решает главную задачу — обход блокировки
Gatekeeper на чужом компьютере.

### Три уровня, от дешёвого к дорогому

| Способ | Что делает пользователь | Требования |
| --- | --- | --- |
| Локальная сборка | ничего, только наш мак | ничего |
| Ad-hoc подпись | «Открыть Anyway» в настройках, либо одна команда в терминале | ничего |
| Developer ID + нотарификация | ничего, просто запускает | Apple Developer Program, $99/год |

Ключевое: подписанныйDeveloper ID и нотарифицированный образ открывается
двойным щелчком. Без этого macOS 26 на чужом компьютере покажет
предупреждение о неподтверждённом разработчике, и пользователю придётся
самому искать, где включить «Открыть Anyway».

### Почему DMG, а не другие варианты

**DMG** — правильный выбор: это просто образ, пользователь перетаскивает
приложение в `/Applications`. Не нужны права администратора, нет
установщика. Именно так распространяется большинство утилит для macOS.

Альтернативы и почему они хуже:

- **PKG** — полноценный установщик с правами администратора. Лишнее,
  если приложение ничего не ставит в систему.
- **App Store** — неподходящий вариант для этого приложения. Период
  ожидания ревью, риск отказа, и главное: **песочница App Store
  ограничивает работу с raw-сокетами**, а это ядро приложения.
  Управление шоу по UDP и TCP в песочнице не заработает. Плюс нужен
  публичный SDK для неё, а это закрывает распространение.
- **GitHub Releases** — рабочий вариант для этапа, пока нет подписи.
  Файл скачивается браузером, но помечается карантинной меткой,
  и у пользователя снова появляется предупреждение.

### Рекомендация

**Developer ID + нотарификация + DMG.** Это стоит $99 в год и снимает
все проблемы с Gatekeeper. Сборка полностью автоматизируется:

```
xcodebuild → подпись Developer ID → notarytool → stapler → DMG
```

Отдельно потребуется сертификат Developer ID (бесплатно в программе)
и `notarytool` с ключом от аккаунта.

Сборку с нотарификацией имеет смысл завести в CI, чтобы не делать
это вручную перед каждым релизом. Само приложение для этого почти
не меняется — добавляется только скрипт сборки.

### Влияние на Info.plist

- `NSLocalNetworkUsageDescription` — обязателен, без него на macOS 15+
  приложение не получит доступ к устройствам в сети. Уже учтено
  в фазе 0.
- `CFBundleShortVersionString` и `CFBundleVersion` — нужны и для
  подписи, и для обновления. Версию держать синхронно с Windows,
  чтобы не путаться.
- Идентификатор бандла наподобие `com.epicplayer.mac` — должен быть
  стабильным, иначе обновление будет воспринято как другое приложение.

### Обновления

Если приложение будет обновляться, стоит рассмотреть Sparkle —
на��иональный фреймворк автообновлений для macOS. Работает с
нотарифицированными сборками. Для шоу-инструмента это полезно:
не нужно вручную приезжать на каждый компьютер техника.
Решение по этому пункту можно принять после первой рабочей сборки.

## Что понадобится для проверки

Этапы 2, 3, 5 и 6 нельзя закрыть без физического доступа к устройству
шоу. Протокол и UI можно писать и проверять локально, но подтвердить,
что пакеты доходят до устройства, иначе не получится.

Работа в сети требует разрешений на подключение — в изолированной
среде они выдаются по запросу.
